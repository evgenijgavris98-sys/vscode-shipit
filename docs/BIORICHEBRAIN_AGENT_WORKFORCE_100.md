# BIORICHEBRAIN — 100-Role Workforce Blueprint

**Status:** organizational design and capability backlog; this document does not claim that 100 independent agents are already running. The current runtime registry is smaller. A role becomes a runnable agent only after it has a typed contract, an allowed capability set, evaluation tests, an owner, and observable execution.

## Operating model

- One ORCHESTRATOR delegates bounded work to specialist roles and synthesizes results.
- MEMORY ENGINE maintains scoped project memory with provenance and contradiction tracking.
- CRITIC / QA verifies important outputs independently of the producing role.
- SECURITY GUARD and APPROVAL GATE remain above all departments; no role can override them.
- Agents receive only the minimum tools/data required. Skill files provide guidance, not permissions.
- High-impact scientific, legal, regulatory, financial, privacy, publishing, deployment and irreversible actions require human approval.
- Model routing is configurable and availability-tested. Do not assume a named model or free tier is available.

## Minimum runtime contract for each role

Every runnable agent must define:
- Stable `id`, department, purpose, input/output schema and owner.
- Allowed model tiers/providers and timeout/token/cost limits.
- Explicit read/write capabilities and data scope.
- Approval triggers and prohibited actions.
- Required source/provenance format and uncertainty labels.
- Evaluation fixtures, pass/fail criteria and independent QA requirements.
- Audit events, failure handling, cancellation and rollback path.

## Maturity levels

- **L0 — catalogued:** role and purpose documented.
- **L1 — prompt-defined:** instructions and structured input/output exist.
- **L2 — registered:** role is in the code registry and routing tests pass.
- **L3 — executable:** provider adapter, permissions, cancellation and audit work in a sandbox.
- **L4 — evaluated:** representative tests and independent QA meet thresholds.
- **L5 — operational:** monitored, versioned, documented, rollback-ready and enabled by an explicit deployment decision.

Do not report “100 agents operational” until every role claimed as operational has passed the required maturity gates. The target is a coordinated workforce of 100 defined roles, not 100 always-running processes.
